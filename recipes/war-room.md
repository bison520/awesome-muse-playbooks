# 作戰室：多 agent 分工＋檔案交接＋人工閘門

> 一句話：幫一人公司或小團隊，把手邊幾個專職 agent 收成一條可覆盤的流水線——情報、草稿各司其職，只用檔案交接，發布前最後一關永遠留給人。

- **適合**：已經有兩三個以上專項 agent（或想拆出專項 agent）的人，想從「同一個對話裡什麼都談」收成「分工流水線」
- **驗證標記**：🔍 改編整理
- **成本量級**：低

## 場景

一個人盯競品、寫內容、做社群雷達、再維護公開文件，很容易變成：一堆 agent 在同一個對話裡互相打斷，或草稿未經確認就被發出去。

作戰室把工作拆成「雷達 → 草稿 → 人工閘門 →（選配）公開文件合併」四段。agent 之間**只透過約定好的檔案與目錄交接**，不互喊、不共享冗長的對話歷史。私密素材先在私密筆記整理，再挑脫敏條目進公開文件。

這個配方是通用版骨架：角色可以增減，時段可以調，重點是「檔案交接」與「人工閘門」兩個原則不動。規模再小，也建議至少保留雷達與草稿兩個角色。

## 輸入

- 3–6 個專項 agent（角色可裁剪，範例）：
  - **雷達**：掃公開網頁、社群關鍵詞、競品更新紀錄
  - **內容**：把雷達要點寫成短文或更新說明草稿
  - **情報**：競品與產業動態摘要（規模小可與雷達合併）
  - **客服向**：只處理已脫敏的用戶詢問草稿（選配）
  - **文件**：整理對外文件差異草稿（選配）
- 共用資料夾約定，例如：`inbox/`（原始線索）、`out/`（各 agent 產出）、`.collab/`（人機非同步留言與任務板）
- 人工閘門：發布、寄信、對外發文前必須人點頭
- （選配）本機或雲端的主力 agent：核實連結、脫敏、合併公開文件；與其他 agent 用任務板加留言檔案非同步同步
- 任務板檔案（`.collab/tasks-{{日期}}.md`），範例：

```text
# 任務板 · {{日期}}
- [ ] 雷達掃描（負責：雷達 agent）→ inbox/radar-{{日期}}.md
- [ ] 草稿撰寫（負責：草稿 agent，前置：雷達完成且不是「無更新」）
- [ ] 人工閘門（負責：人，時段：傍晚）
留言區：
- 只追加、不覆寫別人的留言
```

## 步驟

1. **開板**：在任務板認領當日任務（誰做雷達、誰寫草稿），狀態標 `doing` 加負責人代號
2. **雷達 agent（早）**：按關鍵詞與競品清單掃公開來源，寫入 `inbox/radar-{{日期}}.md`；無實質變化就寫「無更新」並結束
3. **草稿 agent（午）**：只讀雷達檔案，產出 `out/draft-{{日期}}.md`（短文、摘要、待辦清單）；禁止編造輸入裡沒出現的連結
4. **人工閘門（傍晚）**：人打開草稿：改、刪、批「可發」或「作廢」。改動多的句子回寫進提示詞，避免下次重犯同樣的錯。閘門只處理當日草稿，不翻舊帳
5. **（選配）合併**：要進公開倉庫時，主力 agent 按任務板審草稿、脫敏、合併；留言只追加在協作通道，不改別人已寫的內容
6. **收工**：任務改 `done`，產出路徑寫回任務板；私密底稿留在私密筆記，公開倉只收脫敏條目

原則：**檔案交接，不串台聊天**；一個 agent 一次只寫自己的產出檔案。

## Prompt 範例

雷達 agent：

```text
你是 {{產品名}} 的情報雷達。
根據以下公開來源清單與關鍵詞 {{關鍵詞列表}}，彙整最近 24 小時有實質變化的要點，最多 7 條。
每條格式：一句結論 | 類型（產品／定價／內容／其他）| 來源連結 | 信心度（高／中／低）
規則：
- 沒有可靠公開來源的條目不要寫
- 不要推測、不要補上沒出現的功能或數字
- 若全部無實質變化，只輸出一行：無更新 · {{日期}}
把結果寫入約定的雷達檔案，不要呼叫其他 agent。
```

草稿 agent：

```text
你是 {{產品名}} 的內容助理。
只讀取雷達檔案 {{雷達檔案路徑}} 中的要點，產出：
1. 對外短文草稿 1 則（300 字以內，語氣克制，不用誇張詞）
2. 內部摘要 5 條以內（給人審，不直接發）
3. 「需人工」清單：任何缺連結、信心度低、或涉及發布與寄信的事項
禁止：編造來源、承諾上線時間、寫入真實客戶資訊或內部路徑。
變數用 {{佔位符}}。
```

人工閘門檢查清單（給人看，不是給 agent）：

```text
[ ] 每條要點都有可點開的公開來源
[ ] 無金鑰／權杖／營收／內部路徑／可辨識個人資訊
[ ] 短文未承諾尚未上線的功能
[ ] 發布／寄信／對外互動已由人確認，不是 agent 自作主張
```

## 產出

虛構範例（產品名與事件皆為假）：

```text
# inbox/radar-2026-10-22.md
1. AcmeTools 競品「Northwind Docs」更新紀錄新增批次匯出 | 產品 | https://example.com/changelog | 高
2. 話題 {{關鍵詞}} 下出現 3 則可覆核討論 | 內容 | https://example.com/thread/1 | 中
其餘：無實質變化

# out/draft-2026-10-22.md
短文草稿：……（未發）
內部摘要：……
需人工：短文是否發布；是否把脫敏版寫入公開範例

# .collab/tasks-2026-10-22.md（收工時）
- [x] 雷達掃描 → inbox/radar-2026-10-22.md
- [x] 草稿撰寫 → out/draft-2026-10-22.md
- [ ] 人工閘門（待人傍晚處理）
```

## 坑

- **編造來源**：雷達或草稿 agent 會補上「看起來合理」的連結；提示詞強制「無來源不寫」，審核時抽查連結能否打開
- **對話串台**：多個 agent 共用同一個長對話會互相污染上下文；改用檔案交接加任務板認領，一次只跑一個角色
- **缺少人工閘門**：自動寄信或發文最容易出事；發布、寄信、對外互動必須人確認
- **私密與公開混寫**：先在私密筆記整理，再挑條目脫敏進公開倉；公開配方只用 `{{佔位符}}`，範例資料用 AcmeTools 這類虛構名
- **任務板衝突**：兩人同時改同一段時先拉取最新版再合併，保留雙方認領與留言，不覆蓋對方段落
- **前一步空跑**：雷達寫了「無更新」，草稿 agent 仍照常產出湊數內容；草稿 agent 啟動前先檢查雷達檔案存在且不是「無更新」，否則直接結束
- **留言被覆寫**：有人直接改了協作通道裡別人的留言，交接紀錄就斷了；規則是留言只追加、不覆寫，要修正就另起一段寫自己的版本
- **雷達與草稿時段撞車**：草稿 agent 在雷達還沒寫完就啟動，讀到半成品；任務板上草稿任務標註前置條件，雷達沒標 `done` 之前不啟動
