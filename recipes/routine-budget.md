# 排程額度體檢：先止血，再分級，逐條重開

> 一句話：這個配方幫開了一堆排程、額度快燒光的一人公司，用「先全停 → 盤點 → 分級 → 逐條重開」的流程，把資源到底燒在哪裡查清楚，再決定每條排程該留、降速、轉事件觸發，還是直接退休。

- **適合**：排程開到十條以上、常常摸到額度上限，或早上醒來發現一堆排程報錯、卡住的人；剛把工作流搬上雲端 agent 的階段尤其好用
- **驗證標記**：🔍 改編整理
- **成本量級**：低（省的是被浪費掉的額度，不用再花錢裝東西）

## 場景

常見症狀：跑得最快的那條排程在主聊天 agent 裡狂轉；半夜、非工作時段也在刷；會話上下文越積越長；測試時開了隨叫隨跑（on-demand）忘記關；主動建議類能力「自己找事做」。結果是額度暴漲，卻說不清到底哪一條在燒。

本配方不走「裝一個第三方額度監控技能就完事」的路線，而是：**先暫停 → 盤點 → 分級 → 再逐個打開**，把額度護欄寫進日常工作流。適合和 `war-room-ops.md` 的作戰室流程搭配：盤點結果就是作戰室任務板的素材。

## 輸入

- 目前的 agent 清單與排程清單（名稱＋大概的執行頻率即可；**不要把真實帳單截圖貼進任何對外文件**）
- 本週額度大概還剩多少（高／中／低三檔，口頭描述就好，**不要寫具體金額或百分比進配方產出**）
- 哪些 agent 是「主聊天 agent」、哪些是「純雷達／純寫稿」的輕量 agent
- 目前各排程的觸發方式（定時／事件／隨叫隨跑）與大概跑的時段
- （選填）是否裝了第三方額度類監控技能——只考慮只讀、有人工閘門的

## 步驟

1. **急停**：先暫停全部非關鍵排程（尤其 24 小時跑的、半小時級的、主動找事類）。先止血，再歸因。
2. **挪窩**：把高頻雷達／摘要排程從「主聊天 agent」挪到專用輕量 agent；主聊天 agent 只做人工審核與發布閘門。
3. **清上下文**：明顯膨脹的會話，新開一個乾淨會話接著做；長 prompt 改成「指到技能／文件，無新增則靜默」，禁止沒有增量也長篇回報。
4. **排班**：只在工作日白天時段跑（例如本地時區 09:00–19:00）；臨近額度重置日前，暫停可緩跑的排程。
5. **分級**：用下面的 Prompt 範例，讓一隻「體檢 agent」給每條排程打 KEEP／SLOW／EVENT／CHANGE／RETIRE（只估用量、**先不改任何設定**，等人確認）。
6. **逐條重開**：按 KEEP → SLOW → EVENT 的順序重新啟用；每開一條觀察一輪再開下一條。CHANGE 類先改觸發條件；RETIRE 直接刪除或封存。
7. **週覆盤**：每週固定一次「額度體檢」覆盤（可搭配 `weekly-review.md` 類的週報流程），把紅黃綠結果寫回任務板。

## Prompt 範例

體檢 agent（只做額度體檢，只讀建議，不改設定、不發文、不花錢）：

```text
你是 {{產品名}} 的體檢助理，本輪只做排程額度體檢。
不要改任何設定、不要發文、不要花錢。

輸入：我貼上的 agent／排程清單（名稱、執行頻率、觸發方式、是否掛在主聊天 agent 上）。

對每條排程輸出一行表格：
- 名稱
- 建議標籤：KEEP / SLOW / EVENT / CHANGE / RETIRE
- 理由（一句話）
- 預估相對燒量：高 / 中 / 低（不要編造具體金額或百分比）
- 若 SLOW：建議的頻率或時段
- 若 EVENT：改成什麼事件觸發更合適
- 若 CHANGE：改哪一類觸發條件或執行時段
- 若 RETIRE：可否封存

規則：
1. 沒有可靠資訊就標 [需人工]，不要猜。
2. 24 小時跑、半小時級、主動建議、掛在長上下文主聊天 agent 上的雷達，預設傾向 SLOW 或 RETIRE。
3. 第三方監控技能只可以提一句「選配」，不要當成必裝。
4. 最後給 5 步止血順序（先停什麼、再開什麼），用我自己的話，短句。
```

急停確認（給人看的檢查清單，可貼任務板）：

```text
額度急停自查：
[ ] 全部非關鍵排程已暫停
[ ] 跑最快的那條已從主聊天 agent 挪走或關掉
[ ] 測試用的隨叫隨跑已關
[ ] 無增量靜默規則已寫進高頻排程的 prompt
[ ] 工作日白天時段已設定
[ ] 體檢 agent 的分級表已出，等人確認後再逐條啟用
```

## 產出

虛構範例（AcmeTools 為假名）：

```text
額度體檢 · {{日期}}
| 排程名稱     | 標籤   | 燒量 | 下一步                     |
|--------------|--------|------|----------------------------|
| 競品半小時刷 | SLOW   | 高   | 改每日 1 次 · 移到專用雷達 agent |
| 週更摘要     | KEEP   | 低   | 維持                       |
| 主動建議     | RETIRE | 高   | 暫停並觀察一週             |

止血順序：1 暫停全部 → 2 雷達搬出主聊天 agent → 3 清會話
          → 4 開 KEEP → 5 再開 SLOW
```

## 坑

- **只裝額度監控技能卻不暫停**：帳單照樣跑。監控技能描述要寫清「非官方、只讀、要人工閘門」，而且止血靠的是暫停，不是看報表。
- **「無變化也回報」會悄悄燒額度**：高頻排程一定要設「無新增就靜默」；回報內容越長，上下文膨脹越快。
- **會發文的排程沒寫靜默時段**：要把截止時段寫進 prompt 本體。動手前再看一次時間，過了截止時段就跳過本輪，並限定每輪最多發幾條。
- **重型雷達掛在主聊天 agent 上**：上下文和工具呼叫疊在一起，最難歸因。挪到專用輕量 agent，壞了也好單獨除錯。
- **分級表是建議不是執行**：重新啟用仍要人手逐條確認，避免 agent 自己改自己的排程設定。
- **對外文件貼真實帳單**：公開配方、截圖或 PR 裡不要出現真實帳單、具體金額、帳號截圖；範例一律虛構。

失敗查紀錄與補跑的實戰做法見 `cron-checkup.md`。
