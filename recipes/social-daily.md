# 社群日更矩陣：圖文直發＋外連只放首條留言

> 經營多個粉專、每天穩定上稿：圖文在授權範圍內直接發布不逐則確認，外部連結一律放首條留言不放內文，分潤連結入庫管理，發布後讀回驗證。

- **適合**：一人經營 2 個以上粉專／帳號，每天要上稿但不想天天手動發文的人
- **驗證標記**：✅ 真機跑通
- **成本量級**：免費～低（發布工具依用量）

## 場景

多帳號日更的瓶頸從來不是寫不出來，而是「每則都要打開 App、貼上、檢查、發布」的體力活。把流程拆成：agent 按各帳號定位產文案→授權範圍內直接發布→人只處理例外（首條留言、分潤連結、異常）。你每天的工作變成「看一眼發布紀錄」，而不是「一篇一篇發」。

## 輸入

- 各帳號定位卡：名稱（佔位）、受眾、內容範圍、上稿頻率、語氣（每帳號一張卡，agent 選題不跑偏就靠它）
- 圖文規範：語言、口語程度、結尾標籤格式、配圖要求（見下方）
- 分潤連結庫：`affiliate-links.json`（短連結＋對應產品分類＋備註，入庫管理、不要散在文案裡）
- 發布工具：支援排程／即刻發布的工具（只寫類型，不寫真實帳號）
- 授權邊界：哪些類型可直接發、哪些要先過目（見步驟 2）

## 步驟

1. **每日選題**：agent 按各帳號定位卡選題。選題鐵律寫死（例如：價差不到門檻的不寫、需要特定身分才能變現的不寫），不合的直接跳過、不要硬湊。
2. **寫文案＋配圖**：圖文類貼文在授權範圍內**直接發布，不用逐則先給草稿確認**；全新格式（如第一次做影片口播）先送一則樣本過目，通過後才納入自動範圍。
3. **發布**：即刻發布或排程。內文只放文字＋標籤，**外部連結一律不放內文**（平台會降觸及含外部連結的貼文）。
4. **首條留言**：外部連結、完整版連結、分潤短連結，寫成首條留言文案，**由人手動貼**。分潤連結從連結庫取，不要每次現找。
5. **讀回驗證**：發布後立刻讀回——狀態為已發送、內文關鍵字正確、無亂碼。中文內容先轉義再送，避免編碼問題。
6. **存檔**：文案按 `YYYY-MM-DD-<主題>.txt` 存檔；發布紀錄（時間、帳號、狀態）記一筆，方便月底覆盤哪個帳號哪類內容效果好。

## Prompt 範例

圖文改寫（餵給 agent 的原始素材）：

```text
把以下素材改寫成 <帳號定位> 的圖文貼文（繁體中文）：

{{原始素材}}

帳號定位卡：
- 受眾：{{受眾}}
- 語氣：{{語氣}}
- 內容範圍：{{範圍}}

規則：
1. 開頭一句鉤子（≤20 字），不要標題黨
2. 內文生動口語、真實換行分段，結尾附標籤（{{標籤格式}}）
3. 內文不放任何外部連結；連結另外輸出在「首條留言」段
4. 事實查核：數字、價格、規格都要有來源；找不到無水印官方圖就不發圖，先回報
5. 分潤產品只在「首條留言」段出現，從 {{分潤連結庫}} 取對應短連結，不要寫在內文
6. 字數：{{字數上限}}；不要出現簡體字

輸出兩段：與。
```

虛構範例：

```text

⌚ 週三好價：Acme 潛水錶海外到手價，價差夠大才敢推
…（規格＋價格＋一句短評）

🔗 完整規格與購買連結：<短連結>
```

## 坑

- **內文放外部連結**：觸及直接被打折。這條是鐵律，沒有例外——連結永遠在首條留言。
- **發文前沒驗帳號**：多帳號經營最慘的事故是發錯帳號。發布前先打開個人檔案確認名稱，不要只確認「有登入」。
- **發布工具偶發斷線**：回傳被吞不代表失敗。重發前先去確認該則到底有沒有發出去，否則會重複發布。
- **分潤連結散在文案裡**：連結庫是唯一來源，文案裡只出現短連結。散著放，三個月後你會找不到哪條連到哪。
- **新格式直接自動化**：「每日原創圖文」這類新格式，第一則先送人過目，通過才納入自動範圍。格式定型前不要自動發。
- **發布完不讀回**：狀態、關鍵字、亂碼三項讀回驗證，少一項都可能發了壞掉的東西不自知。
