# 週報排程：每週五從固定數據源收痕跡出初稿

> 一句話：幫每週要交代進展的人，讓 agent 每週五去固定幾個地方收集工作痕跡，寫成週報初稿，人花 10 分鐘刪減補強就發。

- **適合**：一人公司或小團隊負責人，每週要給自己、合作夥伴或社群交代進展
- **驗證標記**：🔍 改編整理
- **成本量級**：低

## 場景

週報難寫，往往不是因為沒做事，而是事情散在程式碼倉庫、文件、對話和行事曆裡，週五憑記憶寫，漏掉一半。

讓 Muse 每週五定時去幾個固定地方收集痕跡，按固定結構出初稿。人只負責刪減和補上「為什麼這樣取捨」。

這個配方的關鍵不在文筆，在「固定」二字：固定的數據源、固定的結構、固定的對照基準（上週週報）。固定下來，agent 才不會每週寫出不一樣的東西。

## 輸入

- 數據源（按需挑選，只給唯讀權限）：
  - 程式碼倉庫：本週合併的請求、關閉的議題
  - 文件：本週新建或修改過的文件標題
  - 行事曆：本週的會議標題（不含與會人）
  - 待辦清單：本週完成項和延期項
- 上週的週報（用來對照「上週說要做的，做了沒」）
- 讀者是誰：自己、合作夥伴或社群（決定寫多細）

## 步驟

1. **建排程**：每週五 {{時間}} 觸發，只讀上面幾個數據源
2. **收集**：按數據源分別列出本週痕跡，每條附連結
3. **對照**：拿上週週報裡的「下週計畫」逐條標記：完成、部分完成、未做
4. **成稿**：按固定結構寫初稿，存到 `out/weekly-{{日期}}.md`
5. **人審**：刪掉不該對外的，補上取捨的原因，再發布；至少把開頭三句換成自己的口吻，agent 寫的語氣偏正式

人審檢查清單：

```text
[ ] 沒有營收、用戶數、客戶名等經營與隱私資訊
[ ] 每條「完成」都有連結可點開查證
[ ] 「未做」的原因是人填的，不是 agent 編的
[ ] 卡點寫的是真的需要幫忙的事，不是湊數
[ ] 下週計畫不超過 3 條，且是人真的想做的
```

## Prompt 範例

```text
你是 {{名字}} 的週報助理。現在是 {{日期}}，請整理本週（週一到今天）的進展。
數據源：{{數據源列表}}；上週週報：{{上週週報路徑}}。

按下面結構輸出，每條事實附連結，沒有連結的不寫：
1. 本週完成（最多 5 條，按影響排序）
2. 上週計畫對照：每條標 完成／部分／未做，未做的寫一句原因（不知道原因就寫「待補」）
3. 卡點（需要別人幫忙的事）
4. 下週計畫（最多 3 條）

規則：
- 不寫營收、用戶數、客戶名等經營與隱私資訊
- 不誇大，不寫「大幅提升」這類沒有數據支撐的詞
- 讀者是 {{讀者}}，按這個讀者決定寫多細
```

讀者切換小抄（貼在提示詞後面，agent 會自動調整）：

```text
讀者＝自己：寫細，包含試錯與未完成的心態紀錄。
讀者＝合作夥伴：寫決策與分工，隱私條目先標「待刪」。
讀者＝社群：只留可公開的進展與學到的事，敏感數字全刪。
```

讀者是社群時的脫敏提示詞（成稿後、人審前加跑一輪）：

```text
以下是週報初稿 {{週報檔案路徑}}，讀者是公開社群。
刪除或改寫以下內容：人名、客戶名、營收與用戶數等經營數字、
內部工具路徑、尚未公開的功能名稱。
輸出脫敏後的版本，並在最後列出「被刪除的條目數」，不要列出被刪的原文。
```

## 產出

虛構範例：

```text
# 週報 · 2026-W42

## 本週完成
1. 匯出功能上線 CSV 格式（AcmeTools#42）
2. 競品雷達改成只推實質變化，雜訊從每天 20 條降到 3 條
3. 新增 2 篇配方草稿

## 上週計畫對照
- 上線匯出功能 —— 完成
- 寫 3 篇配方 —— 部分（2/3，第 3 篇待補）
- 約 2 位用戶訪談 —— 未做，待補

## 卡點
- 需要一位懂 iOS 的朋友看一下推播問題

## 下週計畫
1. 補第 3 篇配方
2. 完成 2 位用戶訪談
```

## 坑

- **數據源權限給太大**：只需要讀，不要給寫入權限，更不要給寄信權限
- **無連結的「成果」**：agent 會根據對話紀錄腦補完成項。提示詞要求每條附連結，審稿時抽查
- **原因瞎編**：「未做」的原因 agent 不知道時會編一個。要求它寫「待補」，由人填
- **隱私外洩**：行事曆和對話裡有人名、客戶名，對外發布前人工過一遍
- **排程空跑**：假期那週沒有痕跡，agent 仍會湊一份。加一條：本週少於 2 條痕跡就只寫一句「本週無實質進展」
- **上週週報路徑寫死**：路徑一換 agent 就找不到對照基準；用「最新一份週報」加日期萬用字元定位，不要寫死檔名
- **初稿直接當定稿發**：agent 寫的語氣偏正式，社群讀者會覺得生硬；人審時至少改開頭三句，換成自己的口吻
- **數據源某週剛好沒更新**：程式碼倉庫那週沒合併，不代表沒做事；收集時多看文件與待辦清單，不要只認單一來源
- **下週計畫寫太滿**：agent 會把本週沒做完的全塞進下週；人審時砍到 3 條以內，留緩衝

---

提交前自查：無金鑰、無權杖、無內部路徑、無可辨識個人資訊。

小提醒：週報是「對人交代」的工具，不是 KPI 考核表。寫得誠實比寫得漂亮重要，
沒做完就寫沒做完，卡點寫清楚，下週才排得動。
