# 競品雷達：定時抓公開頁，快照對比只推實質變化

> 一句話：幫需要盯 3–10 個競品、但沒時間每天手動看的人，把「看一遍」變成每日排程，有變化才收到摘要，沒變化就不打擾。

- **適合**：產品負責人、行銷或一人公司，每天想掌握競品官網、定價頁、更新紀錄的動向
- **驗證標記**：🔍 改編整理
- **成本量級**：低

## 場景

手動刷競品官網、更新紀錄、社群帳號很花時間，而且容易漏。競品雷達把這件事變成 Muse 的每日排程：定時抓公開頁面、跟上一次的快照比對，只把有實質差異的部分做成摘要推給你。

注意分工：官網、定價頁、更新紀錄歸競品雷達；社群上的話語與輿情歸 X 雷達。同一事件兩邊都出現時，在摘要裡標註來源已覆蓋，避免雙重推播。

## 輸入

- 競品清單：名稱加公開頁面（官網更新紀錄、定價頁、官方社群帳號）；每個競品註明要盯的頁面類型
- 上一次執行的快照檔案（第一次執行時為空，首輪只建基準）
- 一個排程器：Muse 內建排程即可（或雲端主機的定時任務）
- 雜訊過濾規則：時間戳、推薦版位、瀏覽次數等每次都會變的元素，先列出來，抓取後統一過濾
- 推播目標：信件、即時通訊或筆記三選一（只寫管道類型，不寫真實位址）

競品清單範例（虛構）：

```text
# competitors.md
- Northwind Docs｜更新紀錄 https://example.com/changelog｜定價頁 https://example.com/pricing
- Acme rival B｜更新紀錄 https://example.com/b/updates
- Acme rival C｜官方帳號動態（社群話語歸 X 雷達，這裡只記產品公告）
```

## 步驟

1. **定時觸發**：建議每天 1 次，別太頻繁；抓取頻率保持克制，遵守對方的存取規範與服務條款
2. **抓取**：把每個競品的公開頁面抓下來，存成當天快照；只存清理後的文字重點，不要整頁原始碼，檔名帶日期以便追溯
3. **正規化**：把本次與上次的快照轉成同一種純文字格式（去標籤、去多餘空白），再進入比對
4. **比對**：與上一次快照對比，只保留有差異的部分；先過濾時間戳、推薦版位、純排版變動這類雜訊
5. **摘要**：把差異片段交給 agent 寫摘要；沒有差異就直接結束，不推播
6. **更新**：摘要推播到你常看的地方，快照覆蓋為最新版本；保留最近 7 天的快照，方便回頭查證

## Prompt 範例

```text
以下是競品 {{競品名}} 頁面今天和上次的差異片段。
用不超過 3 條要點說明發生了什麼變化，每條標註類型：
定價／功能／文案／其他。
如果差異只是日期、排版、無意義改動，回覆「無實質變化」。
不要推測沒有出現在差異裡的資訊。
```

差異過濾提示詞（抓取後、比對前先跑一輪）：

```text
以下是兩次抓取的頁面文字。
先刪除以下雜訊再比對：頁首頁尾時間戳、廣告推薦版位、瀏覽次數、
純 CSS 類名或排版差異、與 {{產品名}} 品類無關的側邊欄內容。
輸出清理後的文字，不要加評論。
```

定價變化覆核提示詞（摘要裡出現金額時加跑一輪，避免看錯幣別）：

```text
以下是競品 {{競品名}} 定價頁的差異片段。
只回答三件事：幣別、計費週期（月／年）、金額數字，並附上原文引用。
不要推測折扣原因，不要寫「可能」開頭的句子。
```

## 產出

虛構範例：

```text
競品雷達 · {{日期}}
- 競品 A［定價］入門方案月費上調，新增年付折扣
- 競品 B［功能］更新紀錄新增「團隊空間」
其餘 4 個競品：無實質變化

# 快照目錄
snapshots/acme-rival-a-2026-10-22.txt   ← 本次
snapshots/acme-rival-a-2026-10-21.txt   ← 上次（比對基準）
```

推播訊息範例（有變化時才發）：

```text
競品雷達 · 2026-10-22
- 競品 A［定價］入門方案月費上調，新增年付折扣（USD／月，原文："$29/mo"）
- 競品 B［功能］更新紀錄新增「團隊空間」
其餘 4 個競品：無實質變化
快照已更新；近 7 天快照保留可查。
```

無變化日的落檔範例（也要留一行，方便事後查證有跑）：

```text
# inbox/competitor-radar-2026-10-23.md
競品雷達 · 2026-10-23
6 個競品皆無實質變化（已過濾時間戳與版位雜訊）
快照已更新。
```

## 坑

- **時間戳與推薦版位天天變**：頁面裡的時間戳、推薦版位每天都會變動，比對前先過濾掉，否則天天「有變化」
- **只抓公開頁面**：遵守對方的 robots 與服務條款，頻率保持克制；需要登入才看得到的內容不要硬抓
- **摘要只基於差異片段**：別讓 agent 自由發揮，否則會編出不存在的更新；差異為空就回「無實質變化」
- **抓取失敗被當成「無變化」**：對方擋爬蟲或網路超時，頁面是空的，比對自然沒差異；抓取後先檢查內容長度是否合理，太短就標「抓取失敗」而不是「無實質變化」
- **定價數字看錯幣別或週期**：月費、年費、美元、台幣很容易混；摘要裡的金額一律附原始文字與幣別
- **快照格式不固定**：今天存 HTML、明天存純文字，比對會全盤皆錯；抓取後先正規化成同一種純文字格式再存檔
- **與 X 雷達重複推播**：官網與更新紀錄歸競品雷達，社群話語歸 X 雷達；同一事件兩邊都出現時，在摘要標註來源已覆蓋
- **第一次沒有基準**：首輪執行沒有上次快照可比，不要硬寫「變化」；首輪只建基準並註明「基準建立完成」
- **競品改版換了網址結構**：舊網址 404、新頁面長得完全不一樣，比對會報「全部變化」；先確認是改版還是抓取失敗，改版就重建基準
- **定價頁用圖片呈現**：金額藏在圖片裡，文字抓取抓不到；這類頁面改用人工每月看一次，不要硬塞進每日自動流程
- **一次盯太多競品**：10 個以上每日全抓，摘要會變流水帳；分兩層——核心 3–5 個每日掃，其餘每週掃一次
- **快照越存越多沒人清**：一年下來上千個檔案；約定只留最近 7 天（或 30 天），舊的定期歸檔或刪除

---

提交前自查：無金鑰、無權杖、無內部路徑、無可辨識個人資訊。

小提醒：這條雷達只看官網與更新紀錄這類「官方說了什麼」；社群上「大家在說什麼」歸 X 雷達，兩條線分開才不會重複推播。
