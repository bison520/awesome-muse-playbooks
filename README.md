# awesome-muse-playbooks

> 一人公司 AI agent 實戰配方庫：15 個可直接抄的配方——8 個改編自 Grok 配方庫、7 個是我們每天實際在跑的原創。每條都是「場景 → 輸入 → 步驟 → Prompt 範例 → 產出 → 坑」，坑是親自踩過的。

## 為什麼看這個庫

一個人帶一支 AI 團隊上班，難的從來不是「AI 夠不夠聰明」，而是：角色怎麼拆、檔案怎麼交接、哪一關一定要人點頭。這個庫收集的就是這些「分工與流程」的配方——不是教你怎麼跟 AI 聊天，是教你怎麼讓 AI 團隊自己把活幹完。

這個庫有兩個來源：

- 🔍 **改編整理**：GitHub 上的 `sit-in/awesome-grokbot-playbooks`（中文 Grok Bot 配方庫，MIT 授權）裡可抄的配方，改寫成 Muse 版。Grok 專屬的機制（模板市場、Routine 等）換成了 Muse 的對應做法：技能、排程、共用資料夾、連接器。
- ✅ **真機跑通**：我們自己每天實際在跑的工作流——作戰室派工、AI 熱度榜、意圖雷達、口播影片產線。這些是原倉沒有的，也是這個庫跟原倉最大的不同：**我們的原創配方全部真機跑通過，原倉的配方當時還沒有**。

## Muse 是什麼

Muse 是你的**個人 AI agent**：

- 住在你的電腦，也住在雲端，24 小時在線
- 連接你的帳號與工具（信箱、行事曆、社群、雲端硬碟……）
- 有記憶：記得你做過什麼、你偏好什麼
- 能排程：半夜自己爬起來幹活，早上把成果放你桌上

配方裡的「agent」指的就是這樣的個人 AI 助手——不只 Muse，任何符合上面四點的 AI 助手都適用。

## 3 分鐘上手

1. **挑一個配方**：從下面的配方一覽選一個跟你今天痛點最像的。新手建議先看 `one-person-three-roles.md`（作戰室精簡入門版）。
2. **換掉佔位符**：把 `{{佔位符}}`、`<你的粉專>`、`<你的產品>` 換成你自己的。不要跳過這步就直接跑。
3. **先乾跑一次**：有副作用的步驟（發文、發信、刪檔案）先只產生「計畫」，等人說好才執行。
4. **掛上排程**：跑順了再設成每日／每週自動跑。排程開多之後，記得定期做 `routine-budget.md` 的額度體檢。

## 配方一覽

| 配方 | 一句短評 | 標記 |
|---|---|---|
| `war-room.md` | 多個專職 agent 收成可覆盤流水線：情報、草稿各司其職，只用檔案交接，發布前最後一關永遠留給人。適合想讓多個 agent 分工的人。 | 🔍 |
| `war-room-ops.md` | 一人當 PM 指揮雲端主力＋雜務型 agent 24 小時接力：任務書寫死驗收標準，agent 寫 REPORT 回報。適合手上有 2 個以上 agent 的人。 | ✅ |
| `one-person-three-roles.md` | 作戰室精簡入門版：客服＋內容＋調研三條排程每天各跑一輪，人只花 30 分鐘審核。適合剛上線、沒人手的一人公司。 | 🔍 |
| `x-radar.md` | 每日排程掃一輪社群動態，只把有實質訊號的摘要推給你，沒訊號不打擾。適合沒空整天刷動態牆的人。 | 🔍 |
| `heat-radar.md` | 每天早上掃多來源產 TOP 5 熱度榜單：貼文直發＋靜態網站同步，跑馬燈必須跟當天榜單同源同天。適合經營內容品牌、需要固定欄目的人。 | ✅ |
| `competitor-radar.md` | 每天定時看一遍 3–10 個競品公開頁，快照對比、有變化才推摘要。適合需要盯競品但沒時間手動看的人。 | 🔍 |
| `intent-radar.md` | 只找社群裡主動舉手求助／求推薦的人：評分分級＋個人化回覆＋每則人工審批。適合想做精準外聯、不想被當垃圾訊息的人。 | ✅ |
| `routine-budget.md` | 排程太多燒資源時：先全停→盤點→分級（KEEP／SLOW／EVENT／CHANGE／RETIRE）→逐條重開。適合排程開到十條以上的人。 | 🔍 |
| `cron-checkup.md` | 排程失敗不直接重跑：先查執行紀錄判讀，第三方偶發錯誤有固定重試節奏，補跑脫離連線、三方驗收。適合半夜常收到失敗通知的人。 | ✅ |
| `weekly-review.md` | 每週五 agent 去固定數據源收工作痕跡、寫週報初稿，人 10 分鐘改完就發。適合每週要交代進展的人。 | 🔍 |
| `outbound-support.md` | 多語言工單先脫敏、分流、只出草稿；付款／安全／法律類一律轉人工，agent 不直接發信。適合剛有海外諮詢、請不起客服的人。 | 🔍 |
| `dev-four-roles.md` | 需求→重現→出 PR→驗 PR 拆給不同 agent，產出和裁決分開；人只在批准規格與合併點頭。適合想讓 agent 接 issue 又不敢放手合併的人。 | 🔍 |
| `voiceover-video.md` | 一則 AI 新聞變 20–30 秒 9:16 口播片：TTS 先行定場景、背書截圖、品牌片頭片尾、發布後讀回驗證。適合想穩定日更短影音的人。 | ✅ |
| `money-ideas.md` | 每天一則可執行商機貼文：多來源挖掘、證據分級誠實標註、去個人化改寫、存檔成庫。適合經營一人公司／副業內容的人。 | ✅ |
| `social-daily.md` | 多粉專日更：圖文授權範圍內直發、外連只放首條留言、分潤連結入庫、發布後讀回驗證。適合一人經營多個帳號的人。 | ✅ |

**驗證標記**：✅ 真機跑通＝我們實際在跑；🔍 改編整理＝改編自原倉、骨架保留、已按 Muse 語境重寫。

## 安全提醒

抄配方之前，先看完這五條：

1. **發布、發信、對外互動，永遠留人工閘門**。agent 只出草稿，不直接對外。
2. **不要把真實的 key、token、帳號、信箱寫進配方或 prompt**。公開倉庫只收佔位符版本。
3. **先乾跑再放手**：有副作用的步驟（發文、刪檔、扣款）先產生計畫，等人確認。
4. **脫敏再分享**：人名、客戶名、營收數字、內部路徑，進公開配方前全部拿掉或換成虛構範例。
5. **角色分離保護的是判斷依據，不是權限邊界**：同一帳號下的 agent 共用電腦與登入狀態，敏感操作靠平台本身的權限機制（如分支保護），不要只靠 prompt 約束。
